# M009. 정보구조(IA) 재편 & 신규 인사이트 화면 (계획)

> 본 문서는 **작업 계획 문서**다. 실제 구현은 착수하지 않았으며([M008](./m008-design-system-migration.md)에서 시각 시스템만 적용), 이 문서는 IA 재편과 신규 화면의 범위·매핑·순서를 정리해 후속 착수의 기준으로 삼는다.

## 설명

`docs/product/design/`의 디자인 프로토타입은 시각 시스템뿐 아니라 **새로운 정보구조(IA)** 와 **아직 없는 화면**을 제시한다. 현재 앱은 `가계부(월별 요약) + 자산(하위 탭: 월별/추이/포트폴리오/거래)` 구조이지만, 새 디자인은 자산 중심의 인사이트 구조다. PRD(`docs/product/prd.md`)는 가계부(FR-D)도 유지하므로, 목표는 **자산 인사이트 IA를 새 디자인에 맞추되 가계부를 함께 품는 통합 내비게이션**이다.

## Goals

- [ ] 새 디자인 IA와 현재 라우트의 매핑·갭이 확정되고, 가계부를 포함한 통합 내비게이션 구조가 결정된다
- [ ] 투자 수익 현황(FR-C1) 화면이 정의된다 (종목별/전체 원금·평가액·수익·수익률)
- [x] 자산 변화 분해(FR-C5) 워터폴 화면이 정의된다 (`ΔN = ΔC + ΔV`, `ΔV = ΔP + ΔG`)
- [x] 구성별 분해/개요 등 기존 화면의 재배치·명칭 변경 범위가 결정된다
- [x] 단계별 마이그레이션 순서와 라우트 호환(redirect) 정책이 결정된다

## Goal 상세

### IA 재편 & 통합 내비게이션

새 디자인은 사이드바를 `인사이트 · 기록 · 설정` 그룹으로 나눈다. 현재 `NAV_ITEMS`(월별 요약, 자산 현황)와 `ASSET_SUB_NAV_ITEMS`(월별/추이/포트폴리오/거래)를 이 구조로 재편한다. 결정 필요 사항:

- **가계부 위치**: 별도 최상위 그룹(`가계부`)로 둘지, `기록` 그룹에 합칠지.
- **라우트 명칭**: `portfolio`→`composition`, `monthly`(자산)→`overview`+`input` 분리 여부. 기존 URL은 `next.config.ts` redirect로 호환 유지.
- **개요 화면**: 새 디자인의 대시보드(순자산 히어로 + KPI + 증가 동인 카드 + 계좌 현황)를 신규로 만들지, 기존 `/asset/monthly`를 확장할지.
- **자산 거래(`/asset/transactions`)**: PRD 비목표(거래 단위 기록 제거)와 충돌 — 새 IA에 노출할지/숨길지 결정.

### 투자 수익 현황 (FR-C1) — 신규 화면

종목별·전체 투자 성과 테이블 + 상단 요약 카드. 정의식(출처 `docs/product/insights.md`):

| 지표   | 식                           |
| ------ | ---------------------------- |
| 원금   | `quantity × avgCostKRW`      |
| 평가액 | `quantity × currentPriceKRW` |
| 수익   | `평가액 − 원금`              |
| 수익률 | `수익 / 원금` (원금 0 → "—") |

- 데이터: `holdingService.getWithCurrentValue()`에 이미 손익 계산이 있음(`src/services/holding-service.ts`) — 종목별 집계 + 전체 요약 형태로 노출하는 API/뷰만 추가.
- value형(현금성) 종목은 수익 0이므로 표에서 제외 또는 별도 표기.
- 화면: 손익 색상(`text-gain`/`text-loss`) 테이블 + KPI 카드. 차트는 Nivo 유지.

### ★ 자산 변화 분해 (FR-C5) — 신규 워터폴 화면

`m-1 → m` 총자산 변화를 확정 가능한 상태 변화로 분해:

```
ΔN = ΔC + ΔV
  ΔC = 현금 잔고 변화, ΔV = 투자 평가액 변화
ΔV = ΔP + ΔG
  ΔP = 보유원금 변화, ΔG = 미실현손익 변화
```

- 데이터: `holdingValueSnapshotService.getMonthlyAssetDataWithDelta()`는 현재 총액 델타 중심이다(`src/services/holding-service.ts`). FR-C5 구현 시 현금(C), 투자 평가액(V), 보유원금(P), 미실현손익(G)을 분리 집계하고 시작 총자산 → (+현금 변화) → (+투자 평가액 변화) → 끝 총자산 형태의 워터폴을 추가한다.
- 해석 주의(insights.md §해석 주의): 거래 기록 없이 실현손익·외부 저축액은 확정 귀속하지 않는다. 현금↔투자 이동, 현금화, 보유 수량 증감은 스냅샷 패턴 기반 **추정 인사이트**로 표시한다. `ΔG`는 투자수익 전체가 아니라 미실현손익 변화다.

### 기준 데이터 CRUD (FR-A) — M004/M006와 중첩

구성원/기관/계좌/종목 전체 CRUD UI. 새 디자인의 `설정 · 기준 데이터` 탭형 CRUD를 따른다. M006(자산 기준 데이터 수정/삭제), M004(카테고리/템플릿)와 범위가 겹치므로 착수 시 통합·조정한다.
